# API coverage and boundaries

This is the current implementation map for the browser library. “Raw” means the authenticated SPFx transport is available, but the library does not yet normalize the API’s domain model. It does not claim that every SharePoint server/CSOM method has a browser equivalent.

| Area | Current path | Coverage | Notes |
|---|---|---|---|
| Sites and webs | Graph `getSite`; REST raw | Typed discovery plus raw | `getSite` resolves a host and server-relative path. |
| Users and SharePoint groups | REST `currentuser`, `siteusers`, `sitegroups`, group `users` | Typed bounded pages | Uses the hosting web's authenticated SPHttpClient, validates same-endpoint continuation links, and caps pages at 100. Does not query Entra ID or compute effective access. |
| Lists and columns | Graph `getLists`, `findList`, `inspectList` | Typed read | List and column collections follow Graph next links. |
| List item reads | Graph list items; React `useListItems` | Typed paging, server filters, and cache | `getItemPage` returns an opaque continuation cursor bound to the requested list and filter; `listItems` follows pages with an explicit item bound and supports escaped OData filters. `useListItems` exposes cached-first pages, `loadMore`, and a total item bound. Graph supports `eq`, `ne`, comparisons, and `startswith`; filtering works best on indexed fields. Paged reads cache response pages; `syncList` populates normalized items. |
| Local filtering and sorting | IndexedDB | Typed local query | Only works over items already synchronized into the local store. |
| Incremental list sync | Graph `listItem: delta` | Typed | Persists delta links, applies deletions, pins continuation and delta links to the requested list endpoint, and restarts after a `410` reset response. Unit tests simulate list and drive `410` responses, clear stale cache, and rebuild from the initial endpoint. A live malformed cursor returned `400 invalidRequest`, and the client preserved cached data and its checkpoint. This tenant has not produced a service-driven `410`; Microsoft documents this as a state-recovery response, not a predictable timed expiry. Signed-in delta synced 3,000 mixed-field rows over 15 pages into IndexedDB in 4,279 ms after 113,026 ms of seeding; cold/warm 100-row queries took 6.8/0.0 ms. Earlier 250-item and 2,000-item runs are recorded in the [tenant log](TENANT-VALIDATION.md#passed). This tests synthetic data, not real business-list performance. Delta is current state, not edit history. See Microsoft's [list item delta](https://learn.microsoft.com/en-us/graph/api/listitem-delta?view=graph-rest-1.0) docs. |
| Item create/update/delete | Graph list items | Typed optimistic CRUD | Update uses cached ETag with `If-Match`; conflicts roll back to the cached server item. |
| Common list forms | React `ItemForm`; `ItemAttachmentsPanel` | Fluent UI v9 fields and composable authenticated attachment workflow | Text, number, date, boolean, single/multi choice, Person, and Lookup inputs. `ItemForm` accepts an optional `attachments` slot. The request sample wires it after create when a numeric SharePoint item ID is available. A live fixture probe created, read, updated, and deleted an item with Person and Lookup IDs on disposable lists. |
| Graph batching | Graph `/$batch` | Typed request builder, limited to 20 requests; tenant validated | Subrequest URLs are relative to the version root (for example, `/sites/{id}/lists`). Write bodies default to `Content-Type: application/json` unless a content type is supplied. Five signed-in site/list/column/content-type/item reads passed; check each response status and retry throttled subrequests individually. |
| Other Microsoft Graph APIs | `requestGraph` | Authenticated raw escape hatch | HTTPS `graph.microsoft.com` only; caller supplies endpoint, payload, permissions, and response interpretation. |
| Outlook calendar view | Graph `/me/calendar/calendarView`; `getCalendarView` | Typed, bounded paging | Reads the signed-in user's expanded calendar window without caching; requires delegated `Calendars.ReadBasic` and an active Exchange mailbox enabled for REST. Calendar writes and shared calendars remain raw Graph calls. The 1.24 tenant fixture returned `MailboxNotEnabledForRESTAPI` for its SharePoint-only test account. See Microsoft's [calendarView API](https://learn.microsoft.com/en-us/graph/api/user-list-calendarview?view=graph-rest-1.0). |
| Browser device capture | Native `input[capture]`, `BarcodeDetector`, and `navigator.geolocation` | Example only | No server call; HTTPS and user/host permissions required. Barcode detection support varies. See `DeviceCapture.tsx`. |
| SharePoint REST | SPFx `SPHttpClient` | Authenticated raw transport | Same-origin HTTPS; handles JSON, digest behavior from SPFx, ETags, retry-after on reads, binary request bodies, and raw responses for blob downloads. |
| CAML queries | REST `GetItems` or `RenderListDataAsStream` | Legacy helper; tenant validated | CAML XML remains caller supplied. Both operations returned all three synthetic rows in a disposable list. |
| Render list data as stream | REST | Legacy helper; tenant validated | Returned all three synthetic rows; response shape remains SharePoint-specific. |
| SharePoint change tokens | `GetListItemChangesSinceToken` | Legacy helper; tenant validated | Returns XML; `syncListWithChangeToken` parses rows/deletes and persists a change token. Uses the list-scoped route; `ListName` is not a valid `SP.ChangeLogItemQuery` property in the tested tenant. Three one-row pages passed, and a cross-list cursor returned the `InvalidToken` marker handled by the local cache-reset/full-refresh path. Same-list token expiry remains unverified. Graph delta is preferred for new sync. |
| List change log | REST `GetChanges` | Helper; tenant validated | `SP.ChangeQuery` uses `DeleteObject` (not `Delete`) and string `FetchLimit`; caller supplies the rest of the query. |
| Audience targeting | REST `Fields/CreateFieldAsXml` | Typed helper; tenant validated | Adds or removes the standard `TargetTo` field. Updating `SP.List.EnableAudienceTargeting` fails because that property is not exposed for REST updates. |
| Document libraries and drive items | Graph `drive`/`driveItem`; `getDriveItemPage`, `getDriveItem`, `syncDrive`, `getDriveItems`, `useDriveItems`, `createDriveFolder`, `moveDriveItem`, `copyDriveItem`, `waitForDriveCopy`, `deleteDriveItem`, `getDriveItemPermissions`, `createDriveItemSharingLink`, `deleteDriveItemPermission`, `getDriveItemVersions`, `downloadDriveItemVersion`, `restoreDriveItemVersion`, `readDriveItemContent`, `downloadDriveItem`, `uploadDriveItem`, `DriveUploadInterruptedError`, `useDriveItemContent`, `DriveFloorPlanMap` | Typed cached children paging, resumable bounded root-drive delta sync and normalized drive-item cache with React hook; folder creation, same/cross-drive copy with bounded progress monitor, same-drive move, recycle-bin delete, cached metadata/content reads, uncached current/prior-version downloads, permission/version metadata reads, explicit-scope link creation, confirmed direct-permission removal, confirmed prior-version restore, sequential resumable upload with same-page recovery, and accessible floor-plan rendering from cached private image content | Delta sync stores current drive items and a tenant/user-scoped cursor; the page checkpoint resumes when a bounded call returns `complete: false`. `DriveDeltaPanel` demonstrates sync status, file types, latest-modified inventory, and file actions. `DriveFloorPlanMap` reads private PNG/JPEG/WebP images through `useDriveItemContent`, caches up to 8 MiB by default, and revokes temporary object URLs; the tenant fixture includes a synthetic upload/read/delete probe. The latest signed-in 3,000-folder probe cached all items across 23 delta pages in 11,986 ms; creating folders took 378,049 ms with 19 throttled batch retries, and cleanup took 1,398 ms. The 2,000-folder probe took 8,749 ms to sync across 18 pages; creation took 106,098 ms and cleanup 998 ms. A fixture-injected `410` on an isolated stale cursor cleared its cached sentinel and restarted one bounded authenticated page; this validates client recovery, not tenant-generated expiry. Local timings do not guarantee other tenants' performance. Delta is current state, not edit history. Delegated `Files.Read` is least privilege for work/school drive delta, permission reads, and prior-version download; writes need `Files.ReadWrite`. Copy is asynchronous and the SPFx service polls its same-origin monitor URL. Copies do not retain metadata or source permissions; they inherit destination-folder permissions. `replace` removes the existing destination file and its version history. Sharing link creation requires an explicit scope and preserves inherited permissions. Permission removal re-reads the permission and refuses inherited access. Confirm access changes in the host UI. Cached content is persisted up to 1 MB by default. Downloads always request fresh bytes and bypass cache. Graph permission reads are uncached and caller-visible, not a complete ACL audit. Upload chunks follow Graph's 320 KiB multiple and <60 MiB maximum. If status retries expire, `DriveUploadInterruptedError` keeps the Blob and private session in memory and resumes through `resume()` in the same page; it does not survive reload. The signed-in upload test now covers reconnection within and after the retry window; tenant final-response conflict modes remain unverified. Other tenants and hosts can differ. Cross-drive move remains unsupported. |
| Upload interruption recovery | Graph upload sessions; `uploadDriveItem`, `DriveUploadInterruptedError` | Bounded status retries, same-page resume, and verified completion recovery | Network errors trigger up to six session-status attempts with exponential backoff. If progress remains unknown, the helper throws `DriveUploadInterruptedError`; keep it in page memory and call `resume()` when connectivity returns. It queries `nextExpectedRanges` and continues the same session. The error holds the Blob and private session URL, cannot survive reload, and must not be serialized. After a lost final response, `fail` and `replace` verify the requested destination's name, size, and full bytes after status exhaustion or session expiry. `rename` probes a bounded set of Graph-style numeric and parenthesized suffixes, then compares full bytes before accepting a candidate; if no candidate matches, it reports that completion could not be verified. Fixture 1.0.0.60 passed this path for a 20 MiB + 1 byte upload. For an existing file, `replace` resolves the item and creates the upload session by item ID, as Graph requires. A signed-in 128 MiB + 1 byte upload resumed after six failed status reads. See Microsoft's [create upload session](https://learn.microsoft.com/graph/api/driveitem-createuploadsession?view=graph-rest-1.0) documentation. |
| Markdown files | Graph drive-item content; `useMarkdownFile`; `@spfx-fast/core/markdown` | Cached-first text hook and sanitized React renderer with GitHub-flavored tables | Markdown is untrusted. Raw HTML stays inert; the native SharePoint/OneDrive `.md` viewer does not host SPFx or execute MDX. |
| SharePoint files and folders | SharePoint REST `GetFolderByServerRelativeUrl`, `GetFileByServerRelativeUrl`, `Files`, `Folders` | Raw-only | Binary bodies pass through `rawBody`; use `raw(..., { responseType: "blob" })` for content. REST paths and payloads remain caller supplied. |
| List item attachments | SharePoint REST `AttachmentFiles`; `listItemAttachments`, `readItemAttachment`, `addItemAttachment`, `updateItemAttachment`, `deleteItemAttachment` | Typed list/read/add/update/delete | Applies to classic list-item attachments, not document-library files. Binary reads return Blob; uploads pass the binary body through the authenticated SPFx REST client. |
| File and list item versions | Graph `driveItem/versions`, `listItem/versions`; `getDriveItemVersions`, `getListItemVersions`, `downloadDriveItemVersion`, `restoreDriveItemVersion` | Typed bounded metadata reads, uncached prior-file-version download, and restore as a new current version; list-item version responses include historical field values when returned by Graph. Live SPFx 1.24 validation confirmed three list versions and two file versions, including prior/current byte read-back. | Use `/items/{id}/content` for current bytes; `/versions/{id}/content` rejects the current version. Drive reads need delegated `Files.Read`; restore needs `Files.ReadWrite`. List-item version reads need `Sites.Read.All`; list-item restore and SharePoint REST version operations remain raw-only. Confirm before restore. Retention and versioning settings are service-controlled. See [version-history recipe](EXAMPLES.md#read-list-and-file-version-history). |
| Drive item permissions and sharing links | Graph `driveItem/permissions`, `createLink`; `getDriveItemPermissions`, `createDriveItemSharingLink`, `deleteDriveItemPermission` | Typed uncached permission reads, explicit-scope sharing-link creation, and confirmed removal of verified non-inherited permissions | Work/school delegated `Files.Read` reads permissions; `Files.ReadWrite` creates/removes links. Anonymous links are only created when explicitly requested and may be disabled by tenant policy. Removal re-reads and rejects inherited permissions. Graph may show owners more permissions than non-owners; this is not a complete ACL audit. Never infer access from local cache. |
| SharePoint role assignments and inheritance | SharePoint REST; `getRoleDefinitionsPage`, `getListRoleAssignmentsPage`, auto-paged `getListRoleAssignments`, `getListPermissionScope`, `breakListRoleInheritance`, `resetListRoleInheritance`, `addListRoleAssignment`, `removeListRoleAssignment` | Typed paged role-definition/list-binding reads and confirmation-gated list permission writes | Role-binding aggregation follows at most 100 pages by default (`maxPages` configurable to 1,000); use the page method for incremental UI rendering. Mutations require `confirmed: true`; break-inheritance copies existing bindings and forces `clearSubscopes=false`; reset and removal can revoke access. Scope remains list-only and does not resolve inherited parent assignments, Entra membership, links, or item-level scopes; this is not an effective-access audit. SharePoint authorization is authoritative. See [`ListPermissions.ts`](../examples/ListPermissions.ts) and Microsoft's [custom permissions guide](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/set-custom-permissions-on-a-list-by-using-the-rest-interface). |
| Managed metadata and term store | Graph v1.0; `getTermStoreGroups`, `getTermStoreSets`, `getTermSetChildren`, `getTermChildren` | Typed paged reads for groups, sets, and one-level term hierarchy; writes raw-only | Requires delegated `TermStore.Read.All` with admin consent. Graph returns taxonomy the signed-in user can access; read responses use the standard scoped cache. Helpers load one hierarchy level per call so callers can bound picker work. |
| Lists, fields, views, and content types | Graph list/column reads; `getListContentTypes`; REST `getListViewsPage`, `getListViewFields` | Typed Graph metadata/content-type reads and bounded REST view/field reads | Graph v1.0 exposes list content types at `/sites/{site-id}/lists/{list-id}/contentTypes` and the helper follows all continuation pages. ## Raw-only and service-required SharePoint areas

These entries give agents a focused destination for older SharePoint surfaces that do not have a typed browser helper. Call the authenticated `services.rest` transport only after checking the route and payload for the target API; keep response parsing local to the feature that needs it.

### SharePoint recycle bin, usage, and regional settings

These collections are available through SharePoint REST in tenant-specific shapes. There is no normalized SPFx Fast helper; treat usage as service-provided reporting and avoid assuming the current user's view is tenant-wide.

### SharePoint navigation

Use `getNavigationNodesPage` for a bounded read of the current web's Quick Launch or top navigation. Set `scope: "site"` to read the site collection root web instead. Pass `includeChildren: true` to expand one level; the helper normalizes the nested OData collection to `Children: SharePointNavigationNode[]`. Continue with the opaque `nextCursor`. Navigation edits, audience targeting, and deeper tree expansion remain raw REST; verify legacy versus modern navigation behavior in the target site before changing it. The signed-in SPFx 1.24 validation web returned Quick Launch and TopNavigationBar successfully, with an empty top bar. See [navigation recipe](EXAMPLES.md#read-sharepoint-navigation) and Microsoft's [REST endpoint guidance](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/determine-sharepoint-rest-service-endpoint-uris?tabs=http).

### SharePoint user custom actions

Custom actions are raw REST only. A web's actions and a site collection's actions are separate scopes. Adding script actions can introduce security and governance risk; use only tenant-approved customizations.

### SharePoint publishing

Publishing REST is raw or legacy and depends on enabled site features. Do not infer availability from the presence of an endpoint; inspect the target site and validate the exact operation.

### SharePoint social APIs

Social feeds and followed-content endpoints are legacy and vary by workload and tenant. No typed helper is included; confirm the service is still available before building on it.

### SharePoint workflows

SharePoint 2013 workflows were fully retired from SharePoint Online on April 2, 2026; their workflow engine is no longer available there. SharePoint Server Workflow Manager is a separate on-premises deployment. Do not build new SharePoint Online solutions on SharePoint 2013 workflow endpoints. See Microsoft's [workflow retirement and modernization guidance](https://learn.microsoft.com/en-us/sharepoint/dev/transform/modernize-workflows).

### SharePoint notifications and webhooks

Graph subscriptions and SharePoint webhooks require a reachable callback receiver and renewal lifecycle. SPFx browser code cannot host that receiver; use a service and have notifications trigger a bounded delta sync.

## Permission and throttling notes

- SPFx Graph calls run as the signed-in user through `MSGraphClientV3`; declare the needed scopes in `webApiPermissionRequests` and obtain approval.
- `SPHttpClient` uses the SharePoint host context and current-user cookies/digest handling.
- Graph batch calls can return HTTP 200 while individual operations fail. Inspect every response status.
- Read transports retry 429/503 responses and recognized network `TypeError`s; they honor `Retry-After` when exposed by the host client. Writes are not automatically retried because a retry can duplicate a mutation.
- Configure `onMetric` on both `createClient` and the SPFx transport to receive cache/sync/write metrics and retry-delay events. Metric handlers are isolated so their own exceptions do not fail data calls.
- Cancellation is checked between pages. The host Graph transport may not cancel an already-issued request.
- Raw Graph requests support `GET`, `POST`, `PUT`, `PATCH`, and `DELETE`; set `responseType: "blob"` for Graph content and `rawBody` for file uploads. SharePoint REST raw requests accept `rawBody` and expose `blob()` on the raw response.
- Agent tools are bounded, host-neutral descriptors and do not start an MCP server or grant permissions; the agent host must register them.
- React primitives and generated apps use Fluent UI React v9. `DataGrid` renders a bounded page with accessible previous/next controls; local filtering still evaluates the synchronized list in memory.
- `queryItems` caches exact queries with an explicit limit up to 100 for one second. Store updates invalidate results; use Graph/REST page reads when you need current server state. A cold sorted query reads the full local list.
- Fluent UI React v9 is the only UI dependency and component API used by this toolkit. Validate the v9 combination in the target SPFx host and map SharePoint theme tokens to a Fluent `Theme`.

## CSOM-to-browser crosswalk

| .NET/CSOM surface | Browser path in this toolkit | Classification |
|---|---|---|
| `ClientContext` request execution | Host-authenticated `SPHttpClient` REST calls or `MSGraphClientV3` Graph calls | No `ClientContext` runtime; callers use REST/Graph transports. |
| `Web`, `Site`, `List`, `ListItem`, `Field`, `View`, `ContentType` | Graph typed common reads plus SharePoint REST | Partial typed coverage; remaining members are raw-only. |
| `CamlQuery` and `List.GetItems` | `GetItems` or `RenderListDataAsStream` | Legacy CAML helper; XML and response shape remain caller-owned. |
| `TaxonomySession` and term APIs | Graph term store or SharePoint taxonomy REST | Raw-only; no full CSOM taxonomy model is reproduced. |
| `File`, `Folder`, `Attachment`, `Version` | Graph driveItem/listItem typed metadata, content, upload, folder create, copy, same-drive move, recycle-bin delete, sharing links, direct-permission removal, version-list reads, previous-version download, and file-version restore; SharePoint REST attachment helpers or raw REST | Partial; bounded version metadata reads are uncached; cross-drive move, list-item version restore, and other sharing operations remain raw-only. |
| `SecurableObject`, role assignments, inheritance | Graph drive permissions or SharePoint REST list role assignments and `HasUniqueRoleAssignments` | Typed one-list role changes; broader securable-object management remains raw-only. Parent inheritance, group expansion, links, and item scopes are not resolved. Do not treat one object's roles as complete effective access. |
| `PeopleManager.GetMyProperties`, `GetPropertiesFor`, `GetUserProfilePropertyFor` | SharePoint REST `PeopleManager` through `getMyProperties`, `getPropertiesFor`, `getUserProfilePropertyFor` | Typed read-only subset; visibility and profile population vary. Profile administration, most social methods, and `UserProfileManager` remain unsupported in the browser. |
| Audience targeting | SharePoint REST `Fields/CreateFieldAsXml` with `Type="TargetTo"` | Typed field add/remove helper; verified against a disposable SharePoint Online list. The `SP.List.EnableAudienceTargeting` property update is unsupported by REST. |
| Farm, timer-job, event-receiver, and server object model APIs | No browser endpoint | Unavailable in SPFx; requires a server-side component if supported by the deployment. |
